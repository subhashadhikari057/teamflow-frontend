# Frontend Invite Integration Guide

This document explains the full frontend flow for workspace invite links in Teamflow.
It is written as a handoff for the frontend agent.

## Backend Summary

When a workspace admin or owner invites someone, the backend sends an email with this frontend link:

```text
{FRONTEND_BASE_URL}/invite?token={inviteToken}
```

In local development this usually becomes:

```text
http://localhost:3000/invite?token={inviteToken}
```

The invite token is an opaque UUID generated by the backend. The frontend should treat it as an opaque string and pass it back exactly as received.

## Important Backend Endpoints

### Get Current User

Use this to decide whether the visitor is logged in.

```http
GET /api/auth/me
```

Requires auth cookies or bearer token.

Success means the user is authenticated.

Failure with `401` means the user is not logged in.

### Accept Invite

Use this when the logged-in user clicks **Join Workspace**.

```http
POST /api/mobile/workspaces/invites/accept
Content-Type: application/json

{
  "token": "invite-token-from-url"
}
```

Requires auth.

On success, the backend:

- validates the invite token
- validates the invite is still pending
- validates the invite has not expired
- validates the logged-in user's email matches the invited email
- adds the user as a workspace member with the invited workspace role
- adds the user to the workspace `general` channel as channel `MEMBER`
- marks the invite as accepted
- returns the joined workspace

Success response data is a workspace response containing:

- `id`
- `name`
- `slug`
- `logoUrl`
- `description`
- `plan`
- `isVerified`
- `memberCount`
- `createdAt`

Depending on the frontend API client and global response interceptor, the actual HTTP response may be wrapped:

```json
{
  "success": true,
  "data": {
    "id": "workspace-id",
    "name": "Acme Corp",
    "slug": "acme-corp"
  }
}
```

If responses are wrapped, use `response.data.data` as the joined workspace. If the API client unwraps automatically, use `response.data`.

### Decline Invite

Optional, for a **Decline Invite** button.

```http
POST /api/mobile/workspaces/invites/decline
Content-Type: application/json

{
  "token": "invite-token-from-url"
}
```

Requires auth.

### List Workspaces

Use this after accepting an invite to refresh the user's sidebar/workspace switcher.

```http
GET /api/mobile/workspaces
```

Requires auth.

### Set Current Workspace

Use this after accepting an invite if the frontend should switch the user into the newly joined workspace.

```http
PATCH /api/auth/current-workspace
Content-Type: application/json

{
  "workspaceId": "joined-workspace-id"
}
```

Requires auth.

The backend verifies the user is an active member of that workspace before setting it as the current workspace for the session.

## Main Frontend Route

Create this route:

```text
/invite?token={inviteToken}
```

The page should extract `token` from query params.

If `token` is missing, show an invalid invite state.

Recommended invalid token UI:

- title: `Invalid invite link`
- body: `This invite link is missing or incomplete. Ask the sender for a new invite.`
- action: `Go to login` or `Go home`

## Scenario 1: User Is Already Logged In

### Flow

1. User clicks invite link in email.
2. Frontend opens `/invite?token={token}`.
3. Frontend calls `GET /api/auth/me`.
4. If authenticated, show a confirmation page.
5. User clicks **Join Workspace**.
6. Frontend calls `POST /api/mobile/workspaces/invites/accept`.
7. On success, backend returns the joined workspace.
8. Frontend refreshes workspace list.
9. Frontend switches current workspace or asks the user what to do.
10. Frontend navigates to the joined workspace.

### Recommended UI

Because the backend currently does not have a public invite preview endpoint, the frontend may not know the workspace name before accepting.

Use generic copy:

```text
You have been invited to join a workspace on Teamflow.
```

Primary button:

```text
Join Workspace
```

Optional secondary button:

```text
Not now
```

### Accept Invite Request

```ts
await api.post('/api/mobile/workspaces/invites/accept', {
  token,
});
```

### After Success

The response contains the joined workspace. Use its `id`.

Recommended behavior:

```ts
const joinedWorkspace = response.data.data ?? response.data;

await api.patch('/api/auth/current-workspace', {
  workspaceId: joinedWorkspace.id,
});

await refetchMe();
await refetchWorkspaces();

navigate(`/workspaces/${joinedWorkspace.slug}`);
```

If the frontend routes by workspace ID instead of slug:

```ts
navigate(`/workspaces/${joinedWorkspace.id}`);
```

## Scenario 2: Logged-In User Already Has Another Workspace

This is allowed.

The backend does not enforce one workspace per user.

If the user already belongs to another workspace, accepting the invite simply adds this workspace as another membership.

### Recommended UX Option A: Auto-Switch

After accepting:

1. call `PATCH /api/auth/current-workspace`
2. refresh `me`
3. refresh workspace list
4. navigate to the joined workspace

This is the simplest flow.

### Recommended UX Option B: Ask First

After accepting, show:

```text
You joined the workspace.
```

Buttons:

- `Open Workspace`
- `Stay in Current Workspace`

If they choose `Open Workspace`, call:

```http
PATCH /api/auth/current-workspace
```

Then navigate.

If they choose `Stay in Current Workspace`, only refresh the workspace list/sidebar.

## Scenario 3: User Is Not Logged In But Already Has An Account

### Flow

1. User clicks invite link.
2. Frontend opens `/invite?token={token}`.
3. Frontend calls `GET /api/auth/me`.
4. Backend returns `401`.
5. Frontend stores the invite token and redirect target.
6. Frontend shows login/register screen.
7. User logs in.
8. After login, frontend redirects back to `/invite?token={token}`.
9. Frontend calls `GET /api/auth/me`.
10. Frontend shows **Join Workspace**.
11. User confirms.
12. Frontend calls accept invite endpoint.

### Token Preservation

The token must survive login navigation.

Recommended options:

- Keep it in the URL: `/login?redirect=/invite?token={token}`
- Store it temporarily in session storage

Example:

```ts
sessionStorage.setItem('pendingInviteToken', token);
navigate(`/login?redirect=${encodeURIComponent(`/invite?token=${token}`)}`);
```

After login:

```ts
const redirect = searchParams.get('redirect');
navigate(redirect ?? '/');
```

## Scenario 4: User Is New And Does Not Have An Account

### Flow

1. User clicks invite link.
2. Frontend opens `/invite?token={token}`.
3. Frontend calls `GET /api/auth/me`.
4. Backend returns `401`.
5. Frontend shows account creation option.
6. User registers.
7. User verifies email.
8. User logs in.
9. Frontend redirects back to `/invite?token={token}`.
10. User clicks **Join Workspace**.
11. Frontend calls accept invite endpoint.
12. Frontend sets joined workspace as current workspace.
13. Frontend navigates to the workspace.

### Important Email Rule

The backend only accepts the invite if the logged-in user's email matches the invited email.

If the invite was sent to:

```text
alex@example.com
```

Then the user must register/login with:

```text
alex@example.com
```

If they use a different email, the backend intentionally returns invite not found.

Recommended UI copy during register:

```text
Use the same email address that received the invite.
```

## Scenario 5: User Is Already A Member Of The Invited Workspace

The backend returns `422`.

Message:

```text
You are already a member of this workspace
```

Recommended frontend behavior:

1. Show a friendly already-joined state.
2. Refresh workspace list.
3. Offer `Open Workspace`.

Because the accept response will not return the workspace in this error case, the frontend may need to rely on `GET /api/mobile/workspaces` and let the user pick it, unless a future invite preview endpoint is added.

## Scenario 6: Invite Expired, Revoked, Declined, Or Already Accepted

Possible backend errors:

- invite not found
- invite expired
- invite revoked
- invite already accepted
- invite already declined

Recommended frontend UI:

```text
This invite is no longer valid.
Ask the workspace admin to send you a new invite.
```

Recommended actions:

- `Go to login`
- `Go to workspace list`
- `Contact sender`

## Suggested Frontend State Machine

The invite page can use these states:

```ts
type InvitePageState =
  | 'missing-token'
  | 'checking-auth'
  | 'needs-auth'
  | 'ready-to-confirm'
  | 'accepting'
  | 'accepted'
  | 'already-member'
  | 'invalid-or-expired'
  | 'email-mismatch'
  | 'error';
```

Recommended state transitions:

```text
Page loads
  -> missing-token if no token
  -> checking-auth if token exists

checking-auth
  -> ready-to-confirm if GET /api/auth/me succeeds
  -> needs-auth if GET /api/auth/me returns 401

needs-auth
  -> login/register
  -> redirect back to /invite?token=...

ready-to-confirm
  -> accepting when user clicks Join Workspace

accepting
  -> accepted if accept succeeds
  -> already-member if backend says already a member
  -> invalid-or-expired if expired/revoked/processed/not found
  -> email-mismatch if logged-in email does not match invite email
  -> error for unexpected failures
```

## Suggested React-Style Pseudocode

```ts
function InvitePage() {
  const token = getQueryParam('token');

  if (!token) {
    return <InvalidInvite />;
  }

  const { user, isLoading, isUnauthorized } = useMe();

  if (isLoading) {
    return <InviteLoading />;
  }

  if (isUnauthorized) {
    sessionStorage.setItem('pendingInviteToken', token);
    return (
      <InviteAuthRequired
        onLogin={() => navigate(`/login?redirect=${encodeURIComponent(`/invite?token=${token}`)}`)}
        onRegister={() => navigate(`/register?redirect=${encodeURIComponent(`/invite?token=${token}`)}`)}
      />
    );
  }

  return (
    <ConfirmInvite
      user={user}
      onAccept={async () => {
        const workspace = await acceptInvite(token);

        await setCurrentWorkspace(workspace.id);
        await refetchMe();
        await refetchWorkspaces();

        navigate(`/workspaces/${workspace.slug}`);
      }}
    />
  );
}
```

## API Helper Pseudocode

```ts
async function acceptInvite(token: string) {
  const response = await api.post('/api/mobile/workspaces/invites/accept', {
    token,
  });

  return response.data.data ?? response.data;
}

async function declineInvite(token: string) {
  const response = await api.post('/api/mobile/workspaces/invites/decline', {
    token,
  });

  return response.data;
}

async function setCurrentWorkspace(workspaceId: string) {
  const response = await api.patch('/api/auth/current-workspace', {
    workspaceId,
  });

  return response.data.data ?? response.data;
}
```

## Error Handling Guide

The global error response shape is:

```json
{
  "success": false,
  "statusCode": 422,
  "error": "UNPROCESSABLE_ENTITY",
  "message": "This invite has expired",
  "timestamp": "2026-06-12T10:30:00.000Z",
  "path": "/api/mobile/workspaces/invites/accept"
}
```

Use `statusCode` and `message` for frontend branching.

Recommended mapping:

| Status | Message Pattern | UI State |
|---|---|---|
| 401 | Unauthorized | Send user to login |
| 404 | Invite not found | Invalid invite |
| 422 | This invite has expired | Expired invite |
| 422 | This invite has been revoked | Invalid invite |
| 422 | This invite has already been accepted | Already processed |
| 422 | This invite has been declined | Already processed |
| 422 | You are already a member of this workspace | Already member |

## Current Backend Limitation

There is no public invite preview endpoint yet.

That means before accepting the invite, the frontend cannot safely show:

- workspace name
- inviter name
- invited email
- role being assigned
- expiration date

Recommended future endpoint:

```http
GET /api/mobile/workspaces/invites/preview?token={token}
```

Recommended response:

```json
{
  "workspace": {
    "id": "workspace-id",
    "name": "Acme Corp",
    "slug": "acme-corp",
    "logoUrl": null
  },
  "invitedEmail": "alex@example.com",
  "role": "MEMBER",
  "invitedBy": {
    "id": "user-id",
    "name": "Sam"
  },
  "expiresAt": "2026-06-15T10:30:00.000Z",
  "status": "PENDING"
}
```

Until this endpoint exists, use generic invite copy.

## Checklist For Frontend Agent

- Add `/invite` route.
- Read `token` from query string.
- Handle missing token.
- Check auth with `GET /api/auth/me`.
- Preserve token through login/register.
- After login/register, redirect back to `/invite?token=...`.
- Show confirm UI for authenticated user.
- Call `POST /api/mobile/workspaces/invites/accept`.
- On success, refresh workspace list.
- Set the joined workspace as current workspace with `PATCH /api/auth/current-workspace`.
- Navigate to the joined workspace.
- Handle user already having another workspace.
- Handle already-member response.
- Handle expired/revoked/already-processed invite.
- Remind new users to register with the same email that received the invite.
